■ 2026-08-27(agape250 機):SW **v99** 手機書卷下拉折行修,已部署收斂 ✅
  使用者原話:「8bible 的手機板的經文閱讀的書卷裡的 帖撒羅尼加後書(2 Thess) 變成2行了」。

  ★★ 本輪最該記的一件:**這不是 CSS 問題,而且不先量就會找錯地方。**
    收起來的那一格**根本沒有溢出** —— 320/360/375/390/412 五種手機寬度都量過:
    select 一律 210px、最長的「帖撒羅尼迦後書 (2 Thess)」文字寬 158px、內容區 208px,
    `scrollWidth == clientWidth`,一行放得下。
    折行發生在**下拉展開後的清單**,而原生 <select> 的清單是**作業系統畫的** ——
    white-space / text-overflow / 任何 CSS 都管不到它。⇒ 唯一的槓桿是**把字變短**。
    (也因此「截圖看起來沒事」不代表沒事:截得到的是收起來那一格,截不到系統畫的清單。)

  修法:手機(≤600px,與 CSS 斷點同一個數字)的書卷 option **只留中文全名**。
    中文全名最長 7 字 ≈ 95px(原本 158px,少 40%——那 63px 全是「 (2 Thess)」吃掉的);
    桌機空間夠,維持中英並列(使用者只回報手機)。
  ★ 不是另立規矩:姊妹站 7bible 的書卷 option 本來就只放中文全名
    (src/bible_books.js 的 names[1]),本站是這一族裡唯一的例外,現在兩站在手機上一致。
  ⚠⚠ b.engs 是 **FHL API 的書卷代碼**(sc.php / qb.php / 註釋都靠它查)——
    **只能改顯示、絕不能改資料**。本輪一個字沒動。
  · 順手收斂:閱讀分頁與對讀比較**兩個**書卷下拉本來各寫一份 `${chinesef} (${engs})`,
    現在共用 bookOptionLabel();跨斷點(轉向/改視窗寬)會重貼標籤,**並保留當前選取**
    (不會把人踢回創世記)——這條有實測,手機→桌機→手機來回三次都還在帖後。
  · 側效(量出來的):書卷選單 210→148px ⇒ 手機上「書卷/章/起始節/結束節」四個控制項
    現在排得進**同一行**(原本結束節被擠到第二行),控制列高 223→212px。

  驗法(照抄即可):
    node scripts/validate-deploy.mjs --selftest        # 部署閘門,含白屏 fixture 自測
    netlify deploy --prod --dir . --site c889cd5e-6bec-4008-a0ee-34875aa20585
    node <skills repo>/scripts/deploy-converge.mjs https://8biblesearch.netlify.app --expect bible-multi-v99

    (Google diff-match-patch,Apache-2.0;該授權要求保留署名、不能刪,那不是任何人的個資)。
    ★★ **這裡刻意不寫放行旗標**:0801 實錄=交接文件裡留了一行帶旗標的部署指令,
